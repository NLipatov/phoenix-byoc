# Phoenix BYOC 0.2.7

This release upgrades published 0.2.6 using the selected Preview builds of Web,
frontend, Engine, OpenSandbox, Agents and Gateway.

## Changes

- Agents uses the Pi runtime and portable, versioned agent bundles. Existing
  provider credentials remain supported; optional LLM gateway/provider variables
  can be supplied through `secrets.agents.llmEnv`.
- Web adds agent draft editing and version publication, workflow-agent selection,
  application discovery materials, a deployment model catalog, and ticket issue
  types. Permission answers are deduplicated and protected by a unique index.
- Engine updates the shipped workflow catalog through its migration command,
  preserves customer-edited definitions, improves dev-box removal recovery,
  and supports the provider environment supplied to sandboxed agents.
- Gateway improves Jira description formatting and GitHub pull-request change
  retrieval, and supports Engine-requested cleanup of retained remote workspaces.

## Charts and configuration

Web chart 0.2.7 supplies the model catalog. Engine chart 0.2.9 supports provider
configuration and the updated sandbox lifecycle. Other chart pins are unchanged.
Application images are reused from CI and pinned by digest.

Workflow history cleanup remains disabled. The retired `agentSandboxIdleTTL`
setting no longer controls sandbox lifetime. Retention settings now govern the
shared lifecycle, but this release does not enable deletion.

The default output archive file-count limit increases from 1000 to 200000 for
multi-stage Maestro output. Existing byte limits and explicit customer overrides
are preserved. If an existing values file pins 1000, update that setting before
using workflows that produce more files; see `UPGRADE.md`.

The model catalog follows `vertex.enabled` unless `models` is explicitly set.
Model IDs must be available to the deployment's provider account. Legacy
`vertex.models.*` options belonged to Claude CLI and are ignored by Pi.
No new provider credentials are required for an existing supported route.

## Upgrade

Use the maintained installer and existing values/secrets. Web introduces 15
migrations for permission answers, discovery materials, agent drafts/versions
and publication, workflow selections and ticket metadata. Existing hooks prepare
the incoming Web schema before Engine; no manual SQL or separate migration
script is required when the normal hooks are enabled.

Finish active workflows and pending publications before upgrading. Old AgentFS
sessions require their original Agent image; the installer retains permissions
for those images. Do not force an old session to run in the Pi image. Old-format
repository publications should finish on their original version; a new-version
retry may create a separate `canonix/` publication.

Read `UPGRADE.md` for model settings, installation and recovery limits.
